| CabinetForSolidcraft | `~/CabinetForSolidcraft` | The cabinet rules (`cabinet-core`, `solidcraft-bridge`, `cabinet-sheets`, `cabinet-catalog`) and the older macOS app. The plugin pins its crates by git commit in `Cargo.toml` (now `4d1b579`) |

move the pin. The core's own working branch is `backlog/owner-checks`. Its untracked files

## How to work

```bash
export PATH="/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:/opt/homebrew/bin:$PATH"
cd ~/CabinetStudioPlugin
scripts/build.sh --test          # the gate: catalogue index, manifest, wasm, plugin check, all test cases
scripts/release.sh "notes"       # after bumping "version" in plugin/cabinet-studio/plugin.json and committing
```

- `plugin/cabinet-studio/plugin.json` and `pictures/` are generated by `scripts/make_manifest.py`
  (and `examples/catalog.rs`). Change the generator, then edit the `"version"` field in the
  generated plugin.json, which the generator carries over. The Cabinets panel is declared twice,
  in `make_manifest.py` (`panels()`) and `describe` in `src/lib.rs`, and SolidCraft refuses the
  plugin when they differ.
- Every entry needs test cases in `plugin/cabinet-studio/tests/*.json` (`--require-cases`).
  `scripts/plugin-limits.json` gives the CLI the 5000 host-call ceiling.
- The owner gets a build by restarting SolidCraft and pressing **Update** on the plugin's card in
  Preferences › Plugins (it checks GitHub releases at start). Don't use the control port's
  `plugin.install`: it hangs.
- To try something in the running app: SolidCraft's control port (127.0.0.1:7878, token in
  `~/Library/Application Support/SolidCraft/control/7878.token`), or `solidcraft-cli`. Careful:
  `plugin.run` with `preview: true` over the port builds into the **live** design (only the
  dialog's Preview uses a scratch copy); undo it. The owner's test design is
  `~/Documents/Cabinet Studio plugin tests/before-0.5.0-update.sc`.
- Commit as the owner's git identity, ending messages with a co-author line for the assistant.

## SolidCraft plugin rules learned the hard way

- Manifest at most 64 KiB; it's **61 KB** now. Keep new fields lean.
- A dialog hook may only narrow choices to an ordered subset of the declared ones (max 256), in
  10M fuel / 250 ms. A rejected hook reply shows only in the log; `build.sh` fails on "hook reply
  ignored". Field hints aren't displayed. Dropdowns must be strings (a numeric `oneOf` disables
  the dialog). `x-solidcraft-section` draws a heading on every field that has it: put it on the
  first field of a section only.
- Ribbon: `ribbon_groups` drop-downs come before single buttons; labels fit about 5 letters in a
  group, 8 on a button. Panels always open; a button can't open a panel.
- Long jobs (`job: true`) get no preview; ordinary runs default to 256 host calls (we ask 5000).
- `folders@0.1` can't be combined with the panel/dialog world; files go through the `exports`
  (write) and `jobs` (read) grants.
- A plugin run in the window has no open drawing tile: no sheet sketches. Notes in a drawing are
  centred vertically on their `at` point, about 1.7 × the capital height per line.

## The owner's standing rules

- The interface is the product: simple, logical workflow, pictures over number fields.
- Ask before anything outward or hard to undo: merging to main, Cabinet Studio (app) releases,
  posting GitHub issues or comments, publishing. Plugin releases to this repo are routine.
- Never enter passwords. Never mark catalogue data `verified: true`. Supplier numbers live in
  catalogue data with a source, never as bare literals.
- Save the open SolidCraft design before restarting it; don't kill apps the owner may be using.
- When told to keep working unattended, keep going without asking.
